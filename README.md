# Faultline

The flight recorder for software.

Understand what broke, replay what happened, and explore what could have gone differently.

| | |
| --- | --- |
| **Full app (DeepSpace)** | https://faultline.app.space: sign in, import your own logs, private storage, background imports, shared workspaces |
| **No-account demo (Vercel)** | https://faultline-coral.vercel.app: synthetic incidents and the experiment lab, nothing stored on a server |

The demo incidents are synthetic and labeled as such everywhere they appear.

![Faultline landing page: a live simulated online store during a flash sale](docs/screenshots/landing-1440.png)

## What it does

When software fails, the evidence is scattered: an error in one log, a deploy note somewhere else, an alert, a pile of failed payments. Faultline puts that evidence on one timeline and turns it into a story you can replay.

1. **What happened?** Import logs or traces (JSON, JSON lines, CSV, plain-text logs, OpenTelemetry exports). Faultline normalizes them, removes secrets and email addresses, and builds a timeline.
2. **Why did it happen?** Related events are linked into likely cause-and-effect chains, and possible causes are ranked with the evidence behind each one. They are labeled *inferred* until a person confirms them.
3. **What if?** Pick a moment and a different decision (roll back the update, add database capacity, retry less, rate limit, isolate a dependency, change a timeout). A deterministic simulator replays the incident from that point.
4. **Compare outcomes.** See the original and the alternative side by side: failed requests, success rate, recovery time. A decision that would have made things worse is shown as worse.

## How it works

```
evidence files ──► normalize ──► correlate ──► replay ──────────► incident report
 (logs, traces)    redact,       candidate     binary-search       what happened,
                   dedupe,       edges, noisy- index, check-       impact, possible
                   stable ids    OR scoring    points, reducer     causes + status
                                     │
                                     ▼
                         derived system model ──► discrete-event simulator ──► compare
                         (services, calls,        seeded RNG, queues,          baseline vs
                          capacities)             timeouts, retries,           branch, same
                                                  breakers, rate limits        prefix
```

- **Engine** (`packages/engine`, no runtime dependencies): normalization, correlation and hypothesis ranking, replay, a discrete-event simulator with interventions and branching, report generation, analytics. Runs in the browser (in a Web Worker for simulations) and on the server.
- **Determinism:** every simulation is seeded (`sfc32`), events are ordered by `(time, sequence)` in a binary heap, and branches share an identical prefix with the baseline up to the decision point. Tests assert this.
- **App** (React 19, Tailwind v4, generouted routes): landing page, guided demo, engineering workspace, import flow, lab, reports.
- **Server** (DeepSpace on Cloudflare Workers and Durable Objects): 18 collections with server-side role checks, server actions, a job room for background imports, private per-user file storage, live presence.

## What is real, and what is not claimed

- Every number in the demo comes from running the simulator in your browser. No outcome is hard-coded.
- The three demo incidents are **synthetic**: generated by the simulator, so their logs, alerts and what-if baselines agree.
- Correlation scores are heuristics, not calibrated probabilities. What-if results are model estimates under stated assumptions, and every run lists its assumptions.
- There are no users, customers, testimonials or benchmarks to report.

## Run it locally

Requires Node.js 22+.

```sh
npm install

# Standalone demo (no account, no backend): http://127.0.0.1:5190
npm run dev:standalone

# Full app on DeepSpace (needs `npx deepspace auth login` first)
npm run dev
```

## Tests and checks

```sh
npm run test:engine        # engine unit tests (103)
npm run typecheck:engine
npm run type-check         # whole app
npm run lint
npm run build:vercel       # standalone production build
npx vitest run src/lib src/server src/schemas   # server, schema and SDK-usage tests (21)
npm run test:usability     # usability acceptance tests (11) against the live demo; set FAULTLINE_URL to test another build
npx deepspace test run tests/authz.spec.ts   # 3-account authorization on the DeepSpace runtime (needs 3 test accounts)
npm test                   # DeepSpace smoke/api/collab suites (needs DeepSpace login)
```

Security scanning used during development: Semgrep (`semgrep/semgrep` container) and gitleaks over the full history. See [SECURITY.md](SECURITY.md).

## DeepSpace integrations

Verified on the live app on 2026-11-26 (details and evidence in [the release audit](docs/FINAL-RELEASE-AUDIT.md)):

| Integration | What Faultline uses it for | Verified |
| --- | --- | --- |
| Authentication | Sign-in; every server action rejects anonymous and forged tokens | Yes |
| RecordRoom records + real-time sync | Incidents, events, hypotheses, reviews; live between sessions | Yes |
| R2 file storage (`scope: self`) | Private evidence at `apps/<appId>/users/<userId>/…`, re-checked by the server | Yes, including refused cross-user access |
| JobRoom background jobs | Staged, retryable evidence imports | Yes |
| Server actions + roles | The only write path; owner / collaborator / viewer | Yes (single account live; full role matrix in CI) |
| Deployment | `npx deepspace deploy` from the GitHub source | Yes |
| Integration proxy (AI summary, GitHub commits, web search) | Optional investigation helpers | Implemented, **off by default** (billed to the owner's credits), not verified |

## Known limitations

- Correlation scores are heuristic, not calibrated probabilities.
- Simulations of imported incidents use a model derived from the logs, with disclosed defaults where the logs are silent; results are estimates, not predictions.
- The live three-account authorization run, presence, and the optional integration-proxy features have not been verified on the platform.
- No usability testing with real people has happened yet.
