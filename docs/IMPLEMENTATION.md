## Verified platform facts (read before changing architecture)

These were confirmed against the DeepSpace docs (`docs.deep.space/llms-full.txt`,
fetched 2026-11-25), the official agent skill, and the installed SDK
(`deepspace@0.44.2`, `create-deepspace@0.44.2`):

| Fact | Consequence for Faultline |
| --- | --- |
| Records live in a per-app `RecordRoom` Durable Object; RBAC is evaluated server-side per collection, per row. | Every child collection carries its own access fields. A private parent does **not** protect children. |
| `PermissionLevel` supports `'team'`: owner OR collaborator OR active row in `team_members` for the row's `teamField`. | Workspace isolation = `teamField: 'workspaceId'` + a `team_members` collection that clients cannot write. |
| Server actions run with RBAC **off** (`X-App-Action`). | Every workspace-scoped write goes through an action that checks workspace role first. Clients get `create: false`. |
| `JobRoom` jobs persist in SQLite, broadcast progress over WebSocket, support cancel/retry, and run as the app owner. | Ingestion and persisted simulations run as jobs. The handler re-checks the enqueuer's workspace role (payload is client-supplied). |
| `useR2Files()` default scope `self` is private to the uploader; uploads need `APP_IDENTITY_TOKEN`, minted on first deploy. | Raw evidence goes to `self` scope; the record keeps the key. Upload E2E only works after the first deploy. |
| Auth is same-origin (`/api/auth/token` with cookies); trusted origins are `*.app.space`, `*.deep.space`, `localhost`. | A Vercel-hosted frontend cannot authenticate against the DeepSpace backend. Vercel ships a standalone, clearly labeled demo build. |
| Integrations bill the app owner's DeepSpace credits. | AI, GitHub, and Exa features are optional, owner/member-gated, rate-limited, and never required by the public demo. |
| App source authority latches on first source action; a deploy from a checkout with a GitHub remote claims GitHub. | The GitHub remote was configured before the first deploy. |

## Architecture

```
packages/engine/        Pure TypeScript, zero runtime deps, no DOM, no DeepSpace.
  normalize/            JSON, JSONL/NDJSON, CSV, plain text, OTLP JSON -> CanonicalEvent
  graph/                Service dependency graph, blast radius
  correlate/            Indexed candidate generation, bounded scoring, hypotheses
  replay/               Timestamp index, checkpoints, deterministic state derivation
  simulate/             Seeded discrete-event simulation + interventions + comparison
  scenarios/            Synthetic incidents generated BY the simulator (consistent by construction)
  postmortem/           Deterministic report generation (Markdown / JSON)
  analytics/            Reliability metrics with explicit denominators

src/features/           Shared React UI (investigation workspace, lab, compare, ...)
src/pages/              DeepSpace routes (generouted). Static public pages + (app) data pages.
src/server, worker.ts   Hono worker, actions, jobs (DeepSpace runtime)
src/vercel/             Alternate entry for the Vercel demo build (no DeepSpace providers)
```

The UI is data-source agnostic: the investigation workspace takes an
`IncidentDataset`. The public demo builds one from the synthetic generators;
the authenticated workspace builds one from DeepSpace records.
